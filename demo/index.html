LA Hacks 2026 · Shared-KV role adapters for coding agents

Switch roles.
Keep the cache.

RoleKV makes every role of a coding agent an Activated LoRA on one small model. The Coder and the Reviewer share a single KV cache, so a role switch computes only what is new, not the whole session again.

The problem

Every role switch re-reads the whole session.

The cheap way to build a multi-role agent is one small open model plus a LoRA per role. The roles share the base weights, but a standard LoRA changes the hidden states, and therefore the KV cache, of every token. The Coder's cache is useless to the Reviewer.

So at every switch the engine re-prefills the task, the repository file, the test output and all earlier turns. In an agent that shared context is long and grows every turn, while each role's own answer is short. Most of the compute before an answer goes into text the model has already read.

How it works

One cache. Each role switches on only at its header.

  1. 01

    Read once.

    Everything before a role header, the task, the repository file, the test output and the earlier turns, runs on base weights. That is why every role can share one KV cache.

  2. 02

    Activate at the header.

    An Activated LoRA is switched on only from its invocation sequence onward. Here that sequence is the role header <|role:coder|>, so a role's adapter touches its own turn and nothing before it.

  3. 03

    Hand off exactly.

    The previous role wrote its answer with its adapter on. RoleKV re-reads just that short answer with base weights (H1 canonicalization), 221 tokens per session in our runs, so the cache stays exactly what each role was trained on.

Measured

3.6× to 3.9× fewer tokens computed per session, and the gap widens with context.

bench/cost_sweep.py replays one fixed 4-turn session (buggy code → REVISE → fixed code → APPROVE) with each method at four shared-context sizes. Token counts depend only on the tokens, so they are exact on any machine: a MacBook and an RTX 4090 gave identical figures.

What we compare

Six ways to run two roles on one model.

MethodWhat it isKV cache
Base modelA0Role prompts, no adapter. The quality floor.one cache
One shared LoRAA1Both roles through one adapter. Cheap, but no separate role adapters.one cache
Per-role LoRAsA2One standard LoRA per role, full re-prefill at every switch. The quality reference and the highest cost.no sharing
Naive cache reuseA3Per-role LoRAs that reuse the other role's KV as is.shared, mismatched
RoleKVA5-H1One Activated LoRA per role; the previous answer is re-read with base weights at each handoff.shared, exact
RoleKV, keep handoff KVA5-H2The same adapters, but the previous role's cache entries are kept as they are. Cheaper; differs from training.shared, approximate

Model: Qwen2.5-Coder-1.5B-Instruct. Tasks: MBPP, each with a utils.py of other solutions as the shared repository file. A session is Coder → tests → Reviewer (APPROVE or REVISE, at most two rounds), scored on all asserts.
